# Sicherheit

Dies ist ein Portfolio-Prototyp. Eine überwachte Produktionsinstallation, ein unabhängiger Sicherheitsaudit und feste Reaktionszeiten werden nicht zugesichert.

Bitte keine Zugangsdaten, personenbezogenen Daten oder reproduzierbaren Angriffsinformationen in öffentliche Issues oder Pull Requests schreiben. Falls im GitHub-Repository private Sicherheitsmeldungen aktiviert sind, diesen vertraulichen Meldeweg verwenden. Andernfalls zuerst einen privaten Kontakt zum Repository-Inhaber herstellen; eine verifizierte Kontaktadresse ist derzeit nicht hinterlegt.

Eine vertrauliche Meldung sollte betroffene Version bzw. Commit, Auswirkung und eine minimale Reproduktion mit synthetischen Daten enthalten. Keine fremden Systeme oder produktiven Daten testen.

Bei versehentlich veröffentlichten Secrets reicht das Löschen aus dem aktuellen Dateistand nicht: betroffene Zugangsdaten sperren bzw. erneuern und die Veröffentlichungshistorie gesondert bereinigen. Die hier mitgelieferten Testwerte sind keine produktiven Zugangsdaten.
